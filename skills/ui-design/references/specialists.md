# UI 专长目录

本目录介绍统一库中现有专长的职责和调用条件。路径相对此文件；实际执行前读取所选 `SKILL.md` 及其要求的资源。核查日期：2026-10-27。它描述本地包的现状，不证明其外部 API、版本或授权声明仍然有效。

## 界面构建、体验与艺术方向

### impeccable

- **职责与产物**：产品 UI 构建和精修、UX 评议、技术审查、布局排版、错误状态、响应式与设计系统。输出按请求是界面改动或带证据的审查报告。
- **调用条件**：后台、工具、表单等日常产品 UI 默认主专长；已有页面的局部改进也优先选它。根据任务读取 critique、audit、layout、clarify、polish 等对应流程，以及 product 或 brand register。
- **输入与资源**：具体项目和目标界面；[完整入口](../../impeccable/SKILL.md)、`reference/`、`scripts/context.mjs` 等脚本。执行脚本时用实际包路径，工作目录保持用户项目。
- **边界与已知限制**：部分审美禁令较绝对，应服从用户指定的品牌或 Apple 交互语言。上下文脚本有联网更新检查和本机缓存；离线任务可用现有 `IMPECCABLE_NO_UPDATE_CHECK` 开关。严格不写文件的检查还需避开持久化快照和报告路径，必要时直接读源码。pin/hooks/更新会写配置，需用户实际提出该管理任务。审查不自动转修复。

### frontend-design

- **职责与产物**：把新网页、组件、作品集或品牌页面转化为明确的视觉概念与工作代码，关注排版、颜色、构图与辨识度。
- **调用条件**：从零建立艺术方向，或用户需要鲜明品牌表达。产品后台的单点修复优先使用 Impeccable。
- **输入与资源**：目的、受众、约束、现有品牌及真实素材；[完整入口](../../frontend-design/SKILL.md)，正文自包含。
- **边界与已知限制**：字体与装饰方面有强烈偏好。已有品牌使用系统字体时不擅自换字；复杂视觉效果应有实际目的。它不替代响应式、键盘操作和状态检查。

### design-taste-frontend

- **职责与产物**：Taste 艺术方向、主题素材、文案、构图及浏览器测量；页面和工作型应用有不同流程。
- **调用条件**：仅用户明确点名 Taste、design-taste-frontend 或手动调用。它具有禁止隐式调用的本地政策，总入口保留该限制。
- **输入与资源**：主题、真实内容、品牌素材；[完整入口](../../design-taste-frontend/SKILL.md)。脚本通常要求 Node 22+ 与 Chrome/Edge/Chromium，图片检索需要网络；脚本会写项目 `.taste-skill/` 产物。
- **边界与已知限制**：本地缺少 `library/scenes.json`、具体 scroll-scene 文件及 demo 目录，不能执行该分支或声称已验证。普通 draw/app 资源存在。固定图片数、动效数和审美禁令属于选定 Taste 工作流的偏好，不扩散到其他专长。

### landing-page-generator

- **职责与产物**：广告、活动、注册、线索收集等单目标落地页的信息结构、价值主张、信任信息和 CTA。
- **调用条件**：用户确有单一转化目标；先组织内容，需要界面实现时再配一个视觉主专长。
- **输入与资源**：页面目标、流量来源、受众及真实证据；[完整入口](../../landing-page-generator/SKILL.md)，核心结构自包含。
- **边界与已知限制**：普通多用途首页不默认使用。文中引用的 homepage-generator 等营销专长当前未安装，不能继续分派给它们。若干精确转化数字缺来源，不能作为真实业务数据或保证。

### emil-design-eng

- **职责与产物**：组件手感、反馈、频率、空间关系、动效理由等设计工程判断与解释。
- **调用条件**：用户讨论交互原则，或需要理解某个细节为何影响体验；按主题查阅，避免每次设计都加载全文。
- **输入与资源**：具体交互或理念问题；[完整入口](../../emil-design-eng/SKILL.md)，约 675 行的自包含参考。
- **边界与已知限制**：与动效实施、Apple 设计和审查专长重复较多，含固定英文宣传答复与绝对化经验。遵循用户语言和实际任务，不因该参考扩大输出或替换已有设计系统。

### apple-design

- **职责与产物**：Apple 风格的连续手势、物理弹簧、可中断过渡、材质、景深和排版，主要提供 Web 可实现的设计语言。
- **调用条件**：用户选择 Apple 风格，或任务明确涉及对应物理交互。需要原生 Swift 实现时再配平台技术专长。
- **输入与资源**：目标平台、交互状态和品牌限制；[完整入口](../../apple-design/SKILL.md)，包含代码与可访问性设置建议。
- **边界与已知限制**：Apple 风格不等于 Swift 项目。半透明、blur、系统字体和弹簧建议要结合性能及用户偏好；用户明确选择的弹簧不被其他指南的默认禁令覆盖。引用的权威或版本声明实际使用时核验。

## 动效、组件与平台

### animate

- **职责与产物**：Web 动效从目的、频率、曲线、时长，到中断、退出和实现；提供常见组件 Recipes。
- **调用条件**：用户要求添加或修改 Web 动效。单纯命名、只读机会发现和全库计划使用对应专长。
- **输入与资源**：目标组件、状态转换、交互方式及现有动效库；[完整入口](../../animate/SKILL.md)和包内 `RECIPES.md`。
- **边界与已知限制**：不要因正文推荐自动调用显式选库专长。保留 CSS/Motion/GSAP 等用户既有选择；固定时长和高频操作规则按具体交互判断，验证可中断与 reduced-motion。

### animate-expo

- **职责与产物**：React Native/Expo 的 Reanimated、手势、线程、速度交接、导航过渡与触感实现。
- **调用条件**：已确认 RN/Expo 平台；不是普通网页的替代路径。
- **输入与资源**：Expo SDK、RN 架构、设备与依赖版本；[完整入口](../../animate-expo/SKILL.md)和本包 Recipes。
- **边界与已知限制**：部分默认假设 Reanimated 4、新架构和实验 API。先核对现有项目，避免自动升级依赖。真实设备 release build 没有运行时标记未验证。

### animation-vocabulary

- **职责与产物**：把“弹出来”“像橡皮筋”等描述映射成动效术语，解释相近术语的区别。
- **调用条件**：用户要命名、理解或更准确地描述效果。
- **输入与资源**：文字描述或可观察的动效；[完整入口](../../animation-vocabulary/SKILL.md)，词典自包含。
- **边界与已知限制**：返回英文术语并按用户语言解释；不扩展成 UI 实现、选库或修改词典仓库的任务。

### ask-sonner

- **职责与产物**：Sonner toast 安装接线、样式、主题、异步消息、关闭与常见故障排查。
- **调用条件**：项目已用或用户明确选择 Sonner；如“toast 不显示、重复或样式丢失”。
- **输入与资源**：依赖版本、Toaster 放置和相关调用；[完整入口](../../ask-sonner/SKILL.md)，精确 API 按需读取 `API.md`。
- **边界与已知限制**：普通 toast 需求不自动引入 Sonner。“一个 Toaster”的默认与合法多实例场景要结合上下文；样式经验需匹配实际版本。

### find-animation-opportunities

- **职责与产物**：阅读代码，指出值得添加动效的位置及参数，并说明不值得动的地方。
- **调用条件**：用户要找机会或提出建议，尚未要求实施。
- **输入与资源**：具体页面或仓库；[完整入口](../../find-animation-opportunities/SKILL.md)，按证据给有限建议。
- **边界与已知限制**：保持只读；允许没有合适机会，不为了数量添加建议。时长与键盘操作方面的经验应结合已有产品 token。

### improve-animations

- **职责与产物**：整个代码库的动效审计、优先级和可供后续实施的计划。
- **调用条件**：多组件、全库动效质量或系统性改进路线图。
- **输入与资源**：仓库范围、版本和用户目标；[完整入口](../../improve-animations/SKILL.md)、`AUDIT.md` 与 `PLAN-TEMPLATE.md`。
- **边界与已知限制**：默认只读；入口中 execute 分支与“不实施”定位有冲突。仅评估任务停在报告，已授权实施的部分转给实施专长。不能自动创建用户未要求的外部任务或消息。

### review-animations

- **职责与产物**：对单个组件或动效 diff 给出有证据的审阅和改进意见。
- **调用条件**：用户明确点名 review-animations 或明确授权该专长流程；本包设有 `disable-model-invocation: true`，不因总入口匹配关键词自动启用。
- **输入与资源**：组件、diff 或具体动效；[完整入口](../../review-animations/SKILL.md)及 `STANDARDS.md`。
- **边界与已知限制**：保持审阅范围；“纯淡入必须升级”“只允许 GPU 属性”等偏好不能压过 reduced-motion 与可测的性能事实。普通 UI 审查可使用 Impeccable audit。

### pick-ui-library

- **职责与产物**：从精选前端库中选择适合明确任务的方案并解释取舍。
- **调用条件**：用户明确点名此专长或授权其选库流程；本包禁止隐式调用。普通 UI 开发不顺带启用。
- **输入与资源**：框架、现有依赖、实际需求与限制；[完整入口](../../pick-ui-library/SKILL.md)，库目录自包含。
- **边界与已知限制**：推荐偏向 React。用户已经选定的库与现有可用实现优先；选库建议不自动授权安装、迁移或替换。具体库现状实际推荐时核查。

### prototype

- **职责与产物**：制作几套实质不同的组件或局部 UI 方案，放入可切换的选择器，并等待用户选择。
- **调用条件**：用户明确点名 prototype 或授权其多方案探索流程；本包禁止隐式调用。普通“做个原型”不自动等于多个版本。
- **输入与资源**：要比较的对象、差异维度和真实周边上下文；[完整入口](../../prototype/SKILL.md)与 `PICKER.md`。
- **边界与已知限制**：用户要求完整应用时不擅自缩成单个组件。仅清理本次生成且确认可删除的隔离产物；不替用户提前选胜出方案。

### write-swift

- **职责与产物**：Swift 语言、并发与平台代码的实施或审阅；在 SwiftUI UI 任务中作为技术辅助。
- **调用条件**：项目真实使用 Swift，且任务需要对应语言知识。
- **输入与资源**：工具链版本、平台和代码；[完整入口](../../write-swift/SKILL.md)。
- **边界与已知限制**：不提供完整 SwiftUI 布局设计体系。普通 Swift 并发、数据逻辑直接使用该专长；Apple 视觉风格不触发它。Windows 无 Xcode 时不声称完成原生编译或 Instruments 测试。

## 已选 GSAP 的技术参考

这些专长不重新决定项目的动效库。按任务读取相应模块及需要的章节，保留现有版本、生命周期、组件作用域和无障碍要求。当前包均为自包含 Markdown；以下缺陷来自本地静态检查，未替原作者修复或联网确认 API。

### gsap-core

- **职责与产物**：tween、easing、覆盖、变换、响应式和 `matchMedia` / reduced-motion 基础知识。
- **调用条件**：已经采用 GSAP，确有基础 API 或响应式问题。
- **资源与边界**：[完整入口](../../gsap-core/SKILL.md)。已有代码足够完成目标时不必重复加载；泛“React 动画”不直接授权安装 GSAP。

### gsap-react

- **职责与产物**：React / Next.js 的 useGSAP、refs、context、延迟回调与卸载清理。
- **调用条件**：React 项目已用或用户选择 GSAP；针对生命周期问题加载。
- **资源与边界**：[完整入口](../../gsap-react/SKILL.md)。优先使用已安装依赖；不能把 contextSafe 当作省略事件解绑的依据，实际语义按项目版本确认。

### gsap-frameworks

- **职责与产物**：Vue、Nuxt、Svelte 的挂载、选择器作用域与卸载恢复。
- **调用条件**：非 React 框架中接入已选 GSAP。
- **资源与已知问题**：[完整入口](../../gsap-frameworks/SKILL.md)。引用的 `examples/vue/`、`examples/nuxt/` 本地不存在；Nuxt 同一代码块重复定义 `type Plugins`。采用最小生命周期模式并校核片段，避免直接复制完整示例。

### gsap-timeline

- **职责与产物**：多段动画的顺序、位置参数、标签、嵌套和播放控制。
- **调用条件**：存在真实的多步编排，单个 tween 不必加载。
- **资源与边界**：[完整入口](../../gsap-timeline/SKILL.md)。框架清理和 reduced-motion 需要相应模块补充；defaults 是维护建议，不作为通用正确性判据。

### gsap-scrolltrigger

- **职责与产物**：滚动绑定、pin、scrub、刷新、容器代理与时间线配合。
- **调用条件**：已选 GSAP 的滚动驱动效果；不是所有滚动交互都需要此插件。
- **资源与已知问题**：[完整入口](../../gsap-scrolltrigger/SKILL.md)。横向滚动示例含未定义 `Max.max`、像素差传给 `xPercent`、位移方向和 scrub 配置缺口，不可直接复制。组件卸载采用局部 context 清理，避免全局 kill 其他组件的实例。

### gsap-plugins

- **职责与产物**：Flip、Draggable、SplitText、ScrollTo 等指定插件的注册、使用与恢复。
- **调用条件**：确有指定插件需求；ScrollTrigger 使用专门模块。
- **资源与边界**：[完整入口](../../gsap-plugins/SKILL.md)，按插件名定位章节，避免全文堆叠。插件免费/商用、包路径和版本专有 API 属于时间敏感信息，实际安装或给授权建议时核查官方来源。

### gsap-performance

- **职责与产物**：GSAP 的批量读写、transform、quickTo、长列表和高频更新优化建议。
- **调用条件**：已测量并定位到 GSAP 的性能问题。
- **资源与边界**：[完整入口](../../gsap-performance/SKILL.md)。先建立测量基线；事件监听示例须补生命周期解绑，不把 will-change 当作无条件优化。

### gsap-utils

- **职责与产物**：GSAP 数值范围、插值、随机、集合与选择器辅助函数。
- **调用条件**：已经使用 GSAP，且确实需要其中某个工具函数。
- **资源与已知问题**：[完整入口](../../gsap-utils/SKILL.md)。`unitize` 的值/函数用法与 `shuffle` 是否原地修改需要核对当前官方 API；保护不能被改动的输入数组。一般数学函数不为此引入 GSAP。
