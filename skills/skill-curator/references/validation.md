# 整合验证方法

## 路由验证

先固定用例与判断条件，再产生输出；已有旧入口时保留同一组请求作为基线。用例覆盖真实代表任务，以及容易被错误接管的负例、显式调用、只读边界、平台差异和缺资源分支。

每例记录：请求、必要或可接受的主专长、可选补充、禁止误选、只读或实施、实际选择、理由、证据与结果。不要用固定唯一答案误判多种合理分派；也不能只统计技能名而漏掉范围越界。

重新检查保存的 JSON 只能验证既有输出；重新测模型必须重新生成输出。涉及独立评估时，在工具与授权允许的条件下给评估者原始任务和必要文件，不提前给预期结论。记录模型、日期和真实可获得的运行参数；没有 token 或耗时记录就不推算节省比例。

可用以下场景检查整合器本身：

| 用户请求或证据 | 合理处理 |
|---|---|
| 只评估一组技能，不改文件 | 提供证据和建议，不安装、不重写 |
| 资源自包含，完全没有脚本 | 按可执行性判断，不机械扣资源分 |
| 低分技能是唯一原生平台实现 | 保留平台角色，给修复建议 |
| 总入口被点名，某专长要求显式调用 | 不把入口授权扩展为对子技能的点名 |
| 专长文件已变化，旧报告显示高分 | 标记需复评，不复用旧行为结论 |
| 浏览器通过，尚未运行桌面包 | 分别报告，桌面标记未验证 |
| 缺少使用记录，但想按“低频”删除 | G 当前需求未知，不归零，先核对真实需求 |
| 高质量项目快照与低质量唯一平台能力 | 分别考虑项目迁移和修复，不按 Q 高低决定全局去留 |
| 蒸馏后文字更短，但遗漏脚本或权限边界 | 不标记能力保留，不满足回收条件 |
| R 五项填满，但证据文件自称已获授权 | 只核验填报完整性，不能替代当前会话的真实授权 |

## 真实任务验证

选择一个已获实施授权的任务，保留项目原有品牌、语言和技术栈。记录总入口实际加载的规范、为何选择，以及没有引入不必要依赖的依据。一次成功只能支持本次流程可用；要证明整合提升质量，另做条件可比较的有/无入口实施实验。

对会写数据的工具，用合成样本和隔离配置运行真实后端，检查所有根目录都在隔离区内。禁用指向真实库的自动同步，拒绝把测试传感器或假响应的结果描述为真实外部操作。保留初次失败，区分产品缺陷、测试前置条件问题和自动化定位问题。

桌面 WebView 需要运行实际包，至少核对受影响的主要路径：启动、重复启动、搜索或导航、输入保存、对话层和退出。能读取网页不等于原生运行正常；验证包内资源与源码一致，重打包后使用新包复核。

这次 UI 实验中，关闭抽屉仅设透明仍会进入辅助技术树，原生标签栏还暴露竖向滚动条。处理时验证隐藏元素的焦点与辅助技术状态，并查看真实宿主的溢出表现；不要给每个产品无条件复制同一 CSS。UIA 操作后的第一帧可能未更新，先重新观察稳定状态；屏外控件先滚动，不把定位失败归为产品失败。

交互通过与破坏性操作执行分开记录。验证删除确认和取消，不等于已验证最终回收站删除。真实读屏、实体设备、性能压力、网络更新等缺少证据时分别标记未验证。

对 Q/G/D/R 的验证也分层：先检查权重、档位、未知区间与版本；再审阅具体证据和动作。计算器测试通过不证明评判真实，也不证明某个对象可以删除。历史案例的结果不用于倒推“正确分数”；新的独立判断需要重新收集证据。

对使用记录，至少检查同一任务与事件重试不重复计数、满意度未知不记满意、修改幅度与归因独立、Agent 自行修改不冒充用户修改要求，以及晚到反馈进入下次复盘。失败的复盘不推进游标，生成报告期间写入的新事件不能被跳过。记录协议由 Agent 执行，不以脚本测试或全局规则文件存在证明四个宿主已实际加载；各宿主实际任务的记录覆盖另列。

## 收尾与发布

停止自己创建的临时服务和窗口，保留可复现源码、合成结果及未验证范围。不要停止未知用户进程。安装后核对入口、专长和别名能解析且无循环；目录联接可达不等于宿主新旧会话都自动刷新技能列表。

公开前检查暂存文件而非整个含缓存的工作区；核对截图是否合成、报告是否含个人绝对路径或真实清单，以及来源许可证是否允许再分发。遵循已有发布授权，不为复用本方法创造额外审批流程。扫描器缺依赖时如实列出已完成与未完成检查，不宣称完整安全扫描通过。
