# 文档处理总入口

先识别输入文件、交付格式、已有模板和本地或云端处理约束，再选择实际安装的专长。用户已经指定技能、平台或工具时沿用选择，不因总入口替换其工作流。

## 选择流程

- PDF 页面操作、文字表格提取、表单或生成：`pdf`。
- 扫描 PDF 或图片文字识别、明确指定 OCR 引擎：`pdf-ocr-skill`；有可用文本层时先用 PDF 提取，不无条件 OCR。
- 编辑、读取、合并现有 PPTX/POTX、沿用模板：`pptx`。
- 从材料创作完整 SVG 演示稿，且用户需要这条生成与导出链路：`ppt-master`。
- 网页正文转 Markdown：`defuddle`；`.md` 原始文件直接读取。
- 独立可交互架构或流程 HTML：`archify`；可编辑 Obsidian `.canvas`：`json-canvas`。

详细输入、资源、限制见 [专长目录](references/specialists.md)，只读取与本次分支有关的内容。实际读取选中专长的 `SKILL.md` 后执行，不在本入口重写其格式规范。总入口不是独立 Agent 调度器，也不保证宿主所有文档请求都自动经过它。

## 组合与边界

源 PDF 生成演示稿时，先选提取路径，再选一个制作路径；只有用户要求两种输出或存在明确缺口时才组合两套制作引擎。同名 `pdf` 等可能来自宿主插件与本地库，核对实际路径与能力，避免将两份规范混用。

Word、Excel 或云端演示文稿不归给 PDF/PPTX 技能兜底；先检查宿主已提供的对应技能与连接工具，没有能力时说明缺口。归档个人资料是 `personal-archive` 的单独授权范围，不因处理文件自动归档。

PPT 新建时保留本地 `pptx` 中已有的可见风格样例偏好；用户已选模板、风格或授权直接决定时不重复询问。局部修订沿用现有样式。

## 验证与副作用

处理前确认输入存在及输出位置，默认另存，不覆盖原文件。根据交付检查文本/页数、文件可打开、主要页面视觉与格式，不把成功导出等同于视觉验收。缺少渲染器或设备时标明未验证。

OCR 的模型下载、依赖安装、外部 API、费用与文档上传分别按真实需求和现有授权处理。本地引擎失败就报告原因；不能用“识别质量不够”推定用户同意发送云端。不要读取或输出密钥值。
