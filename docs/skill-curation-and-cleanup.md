# Skill 总入口整理与精简

日期：2026-10-28。本轮使用 skill-curator 整理既有技能，保持独立专长的来源和更新边界，并将通用能力集中在较短的总入口。

## 交付

| 入口 | 整理结果 |
|---|---|
| [document-workflow](../skills/document-workflow/SKILL.md) | 按文档格式选择 PDF、OCR、演示稿、网页提取与图解专长；先提取再制作，避免重复套用制作引擎 |
| [development-workflow](../skills/development-workflow/SKILL.md) | 按规划、实施、同步、归档、测试等阶段选择专长；直接内置最小调试流程 |
| [writing-workflow](../skills/writing-workflow/SKILL.md) | 根据语言选择润色专长，保留事实、引用和作者立场，不把文风判断当作者识别或检测器概率 |
| [f-d-u-d](../skills/f-d-u-d/SKILL.md) | 将技能管理流程重写为按需分派；使用统一库，不自动生成桌面跟踪文件或在任务完成后删除技能 |

入口只保留选择和范围规则。专长的脚本、示例及完整格式规范仍由原包维护；公开仓库不分发许可证或来源未核实的第三方全文。安装与依赖见 [技能说明](../skills/README.md)。

## 中文简介修复

扫描中，名称的通用英文关键词会覆盖技能自带的简短中文用途。例如写作入口被概括成“起草文本”，项目专属说明也会被泛化。

`summarize_skill_zh` 现在优先保留不超过 35 字、含中文的已有描述，并去除外侧空白；其他输入继续使用名称、描述关键词和分类回退。本轮检查中，4 个已精简入口改为显示自带的中文用途，其他 58 个技能概括与提交前一致。此时的检查发生在删除前的 62 项数据上；最终部署为 59 项，不把不同阶段的分母混用。

回归覆盖中文与英文混合的技能名、35 字边界、空描述、长描述回退和英文用途。使用标准库即可运行：

```powershell
python -m unittest discover -s experiments/skill-curation -p "test_*.py" -v
```

## 精简与删除

原库 59 个独立技能，新增三个总入口后为 62 个。四个长入口曾合计从 1516 行精简到 110 行，原文保存在本地快照或按需参考中；这是入口行数变化，不是 token、延迟或成本测试。

在用户确认具体清单后，执行了三项全局技能移除：一个独立调试技能与两个项目专属快照。有效调试原则已经并入开发入口，旧引用清理后再移除文件；物理技能包通过管理器进入 Windows 回收站，四个 Agent 共清理 12 个联接。项目专属原文、运行配置、真实清单和恢复记录留在本地。

调试入口的静态初评为 58/100，依据是固定截断错误上下文、重试后整体重写与最小改动规则矛盾、固定宿主路径及缺失关联资源。保留的通用方法是：复现问题、保留关键上下文、定位原因、最小修改、运行回归；不把重试次数当重写全部代码的依据。

另外两个被移除的项目快照整理后静态分为 82、84，移出全局的理由是用户不再需要全局挂载项目专属内容。它们不是按“低分”等同“无价值”被处理。分数仍为本轮人工工程判断，约有正负 5 分判断误差，不是业务成功率或统计置信区间。

## 验证与边界

- 新建或精简的七个入口做过结构检查；当前公开的四个总入口与本机最终安装内容逐文件核对一致，公开哈希按 UTF-8/LF 规范化，兼容 Git 的换行转换。
- 公开记录保留 [21 个作者静态路由审阅场景](../experiments/skill-curation/routing-review.json)。调试场景已更新为开发入口直接处理，不再引用被移除的独立技能。它不是独立模型盲测、自动触发概率或真实任务成功率。
- OCR 初始化方法在离线替身中检查六条分支，先复现本地失败自动构造云端引擎，再验证失败停止与显式云端选择。可复用修复以 [局部补丁](../patches/README.md) 提供；未导入真实引擎、安装依赖、下载模型或上传文档。
- 真实桌面已检查分类计数、中文简介、入口显示和最终 API 数据；中文简介修复已重新打包，桌面快捷方式同步更新。此后仅改变技能内容与管理器数据，没有再次改写应用界面。
- 未执行真实 OCR 识别、Office 渲染、外部认证或邮件服务、OpenSpec 项目改动、磁盘清理，也未完成全部外部安全扫描器的检查，不报告全面安全认证。

GitHub CI 检查中文简介回归、入口依赖契约与 Python 语法，并使用通用配置构建 Windows 程序。CI 成功不代表某台机器的第三方技能和业务依赖已经安装或可运行。

## 评价口径 v2

本次实践暴露了单一质量分的局限：高质量项目快照仍可能不适合全局挂载，低质量入口可能拥有不可替代资源，已被接收者吸收的可靠内容又不必继续保留独立入口。

skill-curator 因此改用质量 Q、全局保留价值 G、蒸馏潜力 D 三项独立分数，加上不参与加权的五项可回收门槛 R。具体权重、档位、未知处理及动作矩阵见 [评价口径](../skills/skill-curator/references/evaluation.md) 和 [处置体系](../skills/skill-curator/references/disposition.md)。旧分数保留原口径，不补造使用频率或根据已执行结果倒推新分数。

计分脚本只计算输入的分数范围与门槛数量，不推导动作、不核实事实，也不把填报字段当作用户授权。缺证据记未知，不能把缺失部分归零或将已知部分归一化。新增回归通过上面的标准库命令一并执行；回归覆盖计算与权限边界，不等同于模型处置判断已经做过独立盲测。

## 实际使用记录与定期复盘

新增 [使用记录协议](../skills/skill-curator/references/usage-tracking.md) 和标准库 SQLite 脚本。记录实际采用的技能、Agent、任务与入口版本、交付结果和用户反馈；满意度、用户修改幅度与根因分别保存。未评价保留未知，需求变化与环境故障不直接归责技能。只审查候选不算使用，总入口与专长沿用同一任务标识。

记录为追加事件；稳定事件键使重试幂等，不覆盖旧证据。定期复盘以成功游标生成摘要，晚到反馈进入下一轮；报告保存并确认后才推进游标，期间新事件留给下轮。定时任务沿用已有周总结，真实个人配置、使用日志与周报只留本机。

周复盘可按证据复评 Q/G/D，备份后小幅修订并验证；蒸馏、大改与删除提供具体方案由用户选择，回收门槛与真实授权仍单独核验。全局指令接入不是强制 hook，不声称四个 Agent 的每次调用都已自动捕获。11 项隔离日志检查、12 项既有检查及 2 项 YAML 检查共 25 项通过；未对四个宿主逐一运行真实业务任务，也未等待首次定时复盘。

初次官方技能校验因缺少 `yaml` 模块停止，补入独立开发依赖 `requirements-dev.txt` 后，项目环境安装 PyYAML 6.0.3，源码与统一库的 `skill-curator` 均通过官方 `quick_validate.py`；`pip check` 未发现依赖冲突。CI 同时安装该开发依赖，解析公开技能的 YAML 元数据并运行评分、使用记录和复盘游标回归，避免只在当前电脑补齐环境。评分和日志脚本的运行仍仅依赖标准库。
